## Overview

Generative Engine Optimization (GEO) is the practice of structuring platform data specifically for ingestion by Large Language Models (LLMs) and AI search agents. Instead of forcing AI bots to parse and execute complex React/Next.js HTML DOMs, the Treishvaam architecture intercepts these agents at the Cloudflare Edge and serves them highly condensed, semantically structured, cryptographically identified payloads.

**Core principle:** AI crawlers cannot execute JavaScript. Serving them a hydrated React application is computationally wasteful and produces poor AI comprehension quality. GEO payloads are built for token-efficient, semantic-rich AI ingestion.

## Complete GEO Request Flow

```
AI Bot Request (any URL on treishvaamfinance.com)
      │
      ▼
Cloudflare Edge Worker
  isAiBot = aiBotsOnly.test(User-Agent) → TRUE
  request.method === "GET"
  Not: static asset (.css/.js/.jpg etc)
  Not: /api/** path
  Not: /llms.txt or /ontology.json
      │
      ▼ (Aggressive GEO Intercept — Phase 6.5)
handleGeoFeedFromKV(request → /ai-feed.md)
      │
      ├── Tier 1: Cloudflare CDN caches.default → HIT → return (0ms KV read)
      │
      ├── Tier 2: TREISHFIN_SEO_CACHE KV
      │   Key: geo:finance:/ai-feed.md
      │   → HIT → serve + ctx.waitUntil(CDN cache write)
      │
      └── Tier 3: Backend API
          GET /api/public/geo/ai-feed.md
          (signed with generateEdgeSignature)
          → ctx.waitUntil(KV write, expirationTtl: 86400)
          → ctx.waitUntil(CDN cache write)
          Response header: X-GEO-Bot-Detected: true
          Content-Type: text/markdown; charset=utf-8
      │
      ▼
React HTML completely bypassed.
No JavaScript execution. No SSR hydration.
No backend Tomcat HTTP thread consumed for HTML rendering.
```

For explicit GEO path requests (`/llms.txt`, `/ai-feed.md`, `/ontology.json`), any user-agent (human or bot) is served from the same three-tier KV pipeline.

## GEO Backend Endpoints

### Controller: `GeoOptimizationController` (`/api/public/geo/`)

All endpoints are:
- Publicly accessible — no authentication required
- Strictly GDPR-compliant — no PII, internal data, or draft content ever in output
- Rate-limited at the Edge Worker level (not at backend level)

#### `GET /api/public/geo/llms.txt`

- **Content-Type:** `text/plain`
- **Cache-Control:** `public, max-age=3600`
- **Purpose:** Standardized root discovery file (analogous to `robots.txt` for AI agents)
- **Generated by:** `GeoOptimizationService.buildLlmsTxt()`
- **Contains:**
  - Platform purpose and domain authority statement
  - Location of the `ai-feed.md` data pipeline
  - Citation guidelines for AI agents referencing platform content
  - Explicit entity disambiguation: Treishvaam Finance vs Treishvaam Group vs Treishvaamagro

#### `GET /api/public/geo/ai-feed.md`

- **Content-Type:** `text/markdown`
- **Cache-Control:** `public, max-age=3600`
- **Purpose:** Primary GEO data pipeline — aggregated semantic feed for AI agent consumption
- **Generated by:** `GeoOptimizationService.buildAiFeed()`
- **Contains:**
  - Recent published blog articles with titles, slugs, categories, and summaries
  - Current market data highlights (top tickers, recent prices, trend signals)
  - Company vision and strategic overview
  - Structured Markdown sections for token-efficient parsing
- **Security:** Only published, non-draft content is included. The service enforces `status = PUBLISHED` filter at query level.

#### `GET /api/public/geo/ontology.json`

- **Content-Type:** `application/json`
- **Cache-Control:** `public, max-age=3600`
- **Purpose:** Absolute JSON-LD knowledge graph for enterprise LLM ingestion
- **Generated by:** `GeoOptimizationService.buildSemanticOntology()`
- **Contains:**
  - Entity graph: Organization → Services → Products → People → Categories
  - JSON-LD `@context`, `@type`, `@id` annotations per Schema.org specification
  - Domain relationships enabling AI agents to map the platform's knowledge topology without page traversal

## GEO Discovery in HTML Layout

The following tags are embedded in `app/layout.tsx` `<head>` — present on every page load:

```html
<!-- AI Agent Discovery -->
<link rel="llms-txt" href="/llms.txt" />
<link rel="alternate" type="application/json+ld" href="/ontology.json" />
<link rel="search" type="application/opensearchdescription+xml" href="/opensearch.xml" title="Treishvaam Finance" />
```

The Worker additionally injects via `HTMLRewriter` into every HTML response:
```html
<link rel="alternate" type="text/markdown" href="/llms.txt">
<link rel="alternate" type="application/json+ld" href="/ontology.json">
```

The `<body>` is wrapped with:
```html
<semantic-chunk id="main-content" data-aegis-geo="active">
  <!-- all page content -->
</semantic-chunk>
```

This custom HTML element acts as a semantic boundary marker — AI crawlers that do parse HTML can identify the main content zone without executing JavaScript.

## GEO KV Cache Architecture

```
Namespace: TREISHFIN_SEO_CACHE

Key: geo:finance:/llms.txt          TTL: 86400s (24 hours)
Key: geo:finance:/ai-feed.md        TTL: 86400s (24 hours)
Key: geo:finance:/ontology.json     TTL: 86400s (24 hours)
```

On cache miss: Worker fetches from backend with AEGIS Edge Signature → serves immediately → `ctx.waitUntil()` writes to KV asynchronously (non-blocking). The user receives the response without waiting for the KV write to complete.

**Free-tier protection:** GEO KV writes use `ctx.waitUntil()` exclusively — the Worker response is never delayed by KV I/O. This is critical for Cloudflare Free Tier where slow KV writes could cause Worker timeout errors.

## Content Integrity & Provenance

All GEO payloads produced by `GeoOptimizationService` are HMAC-SHA256 signed at generation time using `CONTENT_SIGNING_KEY`. The signature is embedded in payload headers or metadata where applicable. This enables AI agents or downstream validators to verify payload authenticity.

**GDPR compliance lock:** `GeoOptimizationService` enforces a strict whitelist of public fields. It is architecturally impossible to include PII, draft content, user data, or internal system information in any GEO payload.
